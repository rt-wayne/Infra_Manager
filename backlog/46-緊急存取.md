## 1. 目標與範圍

**含**
- SA v0.5 §5.11 緊急存取全部：送出即生效、24 小時補核准期限、申請人回報（僅本人、僅一次）、主管補核准／退回、異常結案（須填結案發現）、受影響帳號子表（D31）
- J03 緊急存取逾期通知（SA §11，每 15 分鐘）
- 首頁兩張卡：「緊急存取待補核准」（待補核准＋逾期未補核准）、「緊急存取異常待追蹤」（已退回且未結案）（SA §7.1）
- 通知鈴鐺類別 3：緊急存取已退回且未結案（SA §7.2）
- 審查異常旗標（IM_ACCT 的 IS_REVIEW_FLAG 等 5 欄）的寫入、顯示、清除（清除時點依 D42：修改或停用申請在關卡 7 複驗通過時）

**不含**：定期審查、統計頁、匯出（仍屬第 14 項（其他第二階段功能））。

規格來源：SA v0.5 §5.11（第 583–609 行）、§4.3 權限（181–184、214、244–246）、資料範圍（270）、§5.5 關卡 7（447）、§5.10 審查異常（460）、§7.1～7.3 首頁卡／鈴鐺／Email（734–772）、ER 圖與資料表（812、847–849）、計算欄（895–896）、單號 EA（927–928）、§11 排程（953–988）、決策 D13／D14（1120–1121）、D29（1136）、D42（1147）；`im_acct_insp_交接文件.md` 第 569、1087、1339、1583–1587、1675–1678、1754 行；`PRD.md` 權限碼、IM_ACCT 旗標欄、IM_ACCT_HIST 預留值、通知、排程端點。

- 主鍵：PK_IM_EMG_ACCESS（EMG_ID）
- 索引：IND_IM_EMG_ACCESS_01（APPLY_BY, SUBMIT_DATE）供「只看自己的單」與依送出時間排序；IND_IM_EMG_ACCESS_02（DECISION_CODE, DEADLINE_DATE）供 J03 與首頁卡。DEADLINE_DATE 必填，所以 DECISION_CODE 為空的列仍會進 B-tree 索引

**狀態判定規則**（不存欄位；「現在」由 Clock 產生並綁參數，不用 SYSDATE）

| 狀態 | 條件 |
|---|---|
| 待補核准 | DECISION_CODE 為空，且現在 ≤ DEADLINE_DATE |
| 逾期未補核准 | DECISION_CODE 為空，且現在 > DEADLINE_DATE（SA 第 896 行「未處理且現在 > 期限」） |
| 已補核准 | DECISION_CODE＝APPROVE |
| 已退回 | DECISION_CODE＝RETURN，且 CLOSE_DATE 為空 |
| 已退回（已結案） | DECISION_CODE＝RETURN，且 CLOSE_DATE 有值 |

- 首頁卡「緊急存取待補核准」＝待補核准＋逾期未補核准＝DECISION_CODE 為空
- 首頁卡「緊急存取異常待追蹤」與鈴鐺類別 3＝已退回
- 補核准達成率（⑭，只做查詢）：分母＝已處理或已逾期（DECISION_CODE 有值，或現在 > DEADLINE_DATE）；達成＝DECIDE_DATE ≤ DEADLINE_DATE（期限內退回也算達成，SA Q05）
- 動作前置條件：回報＝本人（APPLY_BY＝有效身分）且 REPORT_TYPE_CODE 為空且 DECISION_CODE 為空；處理＝DECISION_CODE 為空（逾期後仍可處理）；異常結案＝已退回

### 3.5 synonym 與授權（待釐清，回填後才定 S1 腳本的 synonym 段）

第一階段的 public synonym 與 ap_user 授權怎麼建的，repo 沒有紀錄（只有 `im_acct_insp\src\main\resources\config\database.properties.example` 第 20 行一句「有 Public Synonym」；已登記第 48 項）。使用者以 RD_USER 執行下列三句**唯讀**查詢，結果回填到 3.6：

```sql
-- ① 有沒有 IM_EMG 開頭的表已存在（含其他 schema，避免與機房異動模組撞名）
SELECT OWNER, TABLE_NAME
  FROM ALL_TABLES
 WHERE TABLE_NAME LIKE 'IM\_EMG%' ESCAPE '\'
 ORDER BY OWNER, TABLE_NAME;

-- ② 第一階段的表與序列有哪些 synonym（public 或其他 schema 建的）
SELECT OWNER, SYNONYM_NAME, TABLE_OWNER, TABLE_NAME
  FROM ALL_SYNONYMS
 WHERE TABLE_NAME LIKE 'IM\_ACCT%' ESCAPE '\'
    OR TABLE_NAME LIKE 'SEQ\_IM\_ACCT%' ESCAPE '\'
    OR TABLE_NAME IN ('IM_DOC_SEQ', 'IM_EXEC_MAP', 'IM_ASSET_CLASS', 'IM_INSP', 'IM_INSP_ITEM', 'IM_INSP_RESULT')
 ORDER BY OWNER, SYNONYM_NAME;

-- ③ RD_USER 把第一階段的表與序列授權給誰、什麼權限
SELECT GRANTEE, TABLE_NAME, PRIVILEGE
  FROM USER_TAB_PRIVS
 WHERE TABLE_NAME LIKE 'IM\_ACCT%' ESCAPE '\'
    OR TABLE_NAME LIKE 'SEQ\_IM\_ACCT%' ESCAPE '\'
    OR TABLE_NAME IN ('IM_DOC_SEQ', 'IM_EXEC_MAP', 'IM_ASSET_CLASS', 'IM_INSP', 'IM_INSP_ITEM', 'IM_INSP_RESULT')
 ORDER BY GRANTEE, TABLE_NAME, PRIVILEGE;
```

②③ 除了 `IM_ACCT%` 另含序列與 6 張非 IM_ACCT_ 開頭的第一階段表：ap_user 取序列值、讀 IM_DOC_SEQ 等表同樣需要 synonym 與授權，只查 `IM_ACCT%` 會看不到。

## 7. 待確認（S0 撰寫時發現，等使用者決定；決定後把結果寫回第 2 節或第 3 節，並刪除本節對應條目）

1. **帳號選取器的範圍**：裁示③寫「範圍＝申請人可看的帳號，遵守 D29」，但 D29（PRD 資料範圍「對既有帳號提出異動（查詢）」）是「完整帳號名稱精確比對，不看是否可看該帳號」，而 PRD 的「可看帳號」對一般申請人通常只有自己新增過的帳號。兩者範圍不同，要選一種
2. **切換身分時的實際操作人紀錄**：主表業務欄記有效身分，實際操作人只在 UPDATE_BY（後一次動作會蓋掉前一次）；沒有受影響帳號的動作不寫 IM_ACCT_HIST，代理期間誰真正按了補核准／退回／結案會查不到
3. **EMG_MODIFY 歷史的操作人與時間**：SA 流程圖是主管處理時「依回報登記異動」，ACT_BY／ACT_DATE 記處理的主管與處理時間，還是記申請人與回報時間
4. **D42 清除旗標時是否寫 FLAG_CLEAR 歷史事件**（PRD 已有 FLAG_CLEAR 預留值）
5. **首頁兩張卡對無 EMG_VIEW_ALL 者的點擊行為**：卡片數字是全部（PRD「首頁卡片：全部，只回聚合數字」），清單卻只顯示自己的單，數字對不上；第一階段「30 天內到期」卡的先例是無權限者點擊進無權限頁
6. **異常結案是否也標自核**：裁示⑤只講補核准／退回；EMG_DECIDE 持有人自己申請、被別人退回、再自己結案時，草案沒有欄位記錄
7. **被緊急存取標了旗標的帳號沒有主動提醒**：⑬ 只做緊急存取兩張卡與鈴鐺類別 3，SA 的「審查異常待處理」卡與鈴鐺類別 2 屬定期審查、不在範圍；結案後旗標只在帳號列表／詳情看得到
